# setup UX (#8–#15) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the eight `copi setup` UX issues #8–#15 without weakening any safety confirmation.

**Architecture:**
- The changes live mostly in `runSetup` in `src/wizard.ts`.
- One discovery fix lands in `src/discovery.ts`.
- New pure helpers go in a new module, `src/setup-display.ts`, so they can be unit-tested.

**Tech Stack:** TypeScript (strict), @clack/prompts 1.8.1, node:test, the PTY test helpers.

**Spec:** GitHub Issues #8–#15 are the approved spec. They include the decisions made on 2026-10-11.

## Global Constraints

- Keep the search authorization, the per-file approval for sensitive files, and the final confirm. All of them keep `initialValue: false`. Add no `--yes` flag.
- Previews stay masked. All displayed text keeps going through `safeDisplay`.
- Keep these existing prompt prefixes so existing tests still match:
  - `Choose the locations copi may inspect`
  - `Authorize copi to search only`
  - `Select resources to review`
  - `Create the first resource group`
  - `Save suspected sensitive file <p>`
  - `Save <N> copied resource(s)`
- Renaming in setup changes only the display name. Files, body, and destination stay unchanged (same rule as in the README).
- Full check: Node 22, the sandbox environment, and `NPM_CONFIG_USERCONFIG=/dev/null`.

## Review Focus

- Running setup with cwd equal to HOME: the location select must still work. Do not show a duplicate project option.
- A resource whose name is already in the library: offer only `Skip`, `Rename`, or `Go back`. Never overwrite the saved copy.
- Three or more candidates with the same name: resolution must leave every display name unique.
- Ctrl-C or EOF during the new prompts must cancel with nothing saved, the same as the existing prompts.
- A narrow terminal (80 columns) or `columns` undefined: path truncation must not throw.

### Task 1: Display helpers (#14 and part of #8)

- Create `src/setup-display.ts` with three helpers:
  - `displayPath(p, home)`: replace the home prefix with `~`.
  - `truncateMiddle(s, max)`: keep the head and tail and join them with `…`. Return `s` unchanged when `max` is small or missing.
  - `formatBytes(n)`.
- Test them in `test/setup-display.test.ts`.

### Task 2: Discovery warning fix (#10)

- In `src/discovery.ts`, `addCandidate`: when `lstat(sourcePath)` fails with ENOENT, return without a warning.
- Keep the `resource-outside-root` warning for entries that exist but resolve outside the search root (symlinks), and for dangling symlinks.
- Test: a missing file produces no warning. The existing symlink tests (`discovery.test.ts:226`, `:249`) still pass.
- In `runSetup`, summarize the remaining warnings:
  - Title: `Skipped N resource(s) outside the selected locations`.
  - Paths shown with `~`.
  - Show the first 5, then `+N more`.

### Task 3: Location select (#11)

### Task 4: Candidate list labels (#8)

- Label format: `[kind] name — <~dirname(sourcePath)>`, plus ` (already saved)` when the name's `nameKey` is already in the catalog.
- Hint format: `<size or file count> · modified <YYYY-MM-DD> · <destination>`. Truncate it to fit the terminal width.
- Sort by kind, then `nameKey`, then source path.
- PTY test: two candidates with the same name show different source labels without focus. `already saved` appears for a name that is already in the library.

### Task 5: Early name-conflict resolution (#9)

- Right after the resource multiselect, group the selected candidates by `nameKey` and also check them against the catalog.
- When names collide within the selection, show a `select` with these options:
  - `Keep <name> — <src>` (one option per candidate).
  - `Keep all and rename the others`.
  - `Go back to the list`.
- Renaming uses `text`:
  - The default is `<name> (<last path segment of source dir parent>)`.
  - Validate with `nameKey`, against the library names and the other pending names.
- When a name collides with the library, show `Skip (keep the saved copy)`, `Rename`, or `Go back to the list`.
- `Go back` re-runs the multiselect with the previous selection as `initialValues`.
- Rename by copying the candidate with the new `name` before `prepareCandidateForReview`.
- Keep the final batch validation as a safety net.
- Update the issue2 duplicate test: it now hits the resolution prompt instead of `Duplicate item name`. Add tests for keep-one, rename (saved name differs, files are identical), skip, and go back.

### Task 6: Group explanation and bulk assignment (#12)

- When the library has no groups, the group-name prompt reads `Name a group for these resources (used later with: copi apply <group>)`.
  - Keep the prefix `Create the first resource group`, giving: `Create the first resource group — used later with: copi apply <group>`.
  - Placeholder: `e.g. game-review`.
- Choose the assignment mode:
  - One resource and one group: assign it directly, with no prompt.
  - Several resources and one group: `select` between `Put all N resources in "<g>"` (default) and `Choose groups for each resource`.
  - Several groups: `select` between `Put all N resources in the same groups` (default), followed by one multiselect, and `Choose groups for each resource`.
  - One resource and several groups: go straight to one multiselect.
- In per-resource mode, the group hints show pending counts, for example `2 saved · 1 pending`.
- Update the test steps (the `Assign` steps disappear in bulk mode). Add tests for bulk with N=4 (no `Assign` prompt; the summary shows `→ g` four times) and for per-resource mode.
